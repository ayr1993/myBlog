# 前端开发者怎么做静态站SEO，以VitePress为例

很多做前端的朋友会觉得SEO是运营岗位的工作。但对于VitePress、Hexo这类静态网站，**SEO的基础骨架，全部是前端来搭建**。静态站本身天生对爬虫友好，但不做优化，收录和排名依然会很差。

## 一、先搞懂静态站的优势

VitePress打包后输出纯静态HTML文件，浏览器、搜索引擎爬虫拿到的是完整渲染好的页面内容。对比Vue、React纯客户端渲染SPA页面：

- SPA：爬虫拿到的是空HTML，需要执行JS才能渲染内容，很容易抓取失败

- VitePress静态输出：HTML里直接包含正文、标题、文本，爬虫可以直接读取，收录门槛低很多

这也是为什么个人技术博客、文档站，优先选择VitePress。

## 二、每篇文章必写：Frontmatter元信息

frontmatter是VitePress内置的页面配置，对应网页的title、description，是SEO最基础的部分。

```md
---
title: 页面标题
description: 页面描述，控制在70～120字，写清楚本篇文章能解决什么问题
tags: [标签1,标签2]
---
```

⚠️ 重要规则：

1. 每个页面的title、description不能重复，不要全站共用一套

2. description不要堆砌关键词，自然描述内容即可

3. title尽量前置核心关键词

## 三、站点地图 sitemap\.xml

sitemap的作用：告诉搜索引擎你的网站一共有哪些页面，引导爬虫批量抓取。VitePress可以直接使用 `vitepress-plugin-sitemap` 插件，打包的时候自动生成sitemap\.xml。

安装：

```bash
npm i vitepress-plugin-sitemap -D
```

在 `.vitepress/config.mts` 中引入插件并配置网站域名，打包后就会自动产出站点地图，提交到百度搜索资源平台、谷歌搜索控制台。

## 四、网页性能优化（Core Web Vitals）

网页核心体验指标，现在是搜索引擎评估站点质量的参考项：

- **LCP 最大内容绘制**：首屏最大内容加载速度，目标 \< 2\.5s。优化：图片压缩为WebP，使用CDN，减少首屏大图片

- **INP 交互响应**：点击、输入后的响应速度，目标 \< 200ms。优化：拆分长耗时JS任务，页面不要嵌入太多无关脚本

- **CLS 布局偏移**：页面加载时元素跳动，目标 \< 0\.1。优化：图片、视频标签固定宽高，加载时不会突然撑开页面

## 五、语义化标签与正文结构

写文章的时候，HTML层级要规范：

- 一个页面只保留一个 `#`（h1），也就是文章主标题

- 二级标题 `##`、三级标题 `###` 顺着层级往下，不要跳级

- 图片必须写上 `alt` 属性，alt用来向爬虫描述图片内容

- 超链接 `<a>` 区分普通跳转链接，不要大量使用空链接 `javascript:void(0)`

## 六、内链规划

内链就是文章里面互相引用的链接。比如本篇讲到sitemap，你可以加链接跳转到sitemap单独教程页面。好处：

1. 爬虫顺着链接发现更多页面

2. 传递页面权重

3. 方便读者在博客内阅读更多相关内容

> 小技巧：不要一次性堆大量内链，正文相关的地方自然插入最合适。

## 七、robots\.txt 爬虫规则

在项目 `public` 文件夹新建 `robots.txt`，用来告诉爬虫哪些页面可以抓、哪些禁止抓取。示例：

```txt
User-agent: *
Allow: /
Sitemap: https://你的域名/sitemap.xml
```

不需要被收录的页面（比如测试页、草稿页），可以在这里屏蔽。

## 八、常见踩坑提醒

1. ❌ 不要关键词堆砌：标题、描述、正文反复重复同一个词，容易判定作弊降权

2. ❌ 不要大量复制网上内容：重复内容收录难度极高，尽量原创或者深度改写

3. ❌ 不要随便删已经被收录的文章：如果必须删除，配置404页面或者301重定向

4. ✅ 稳定更新：定期发布原创内容，搜索引擎会提高爬虫来访频率

## 总结

VitePress给我们准备好了SEO的地基，前端只需要做好：规范元信息、输出站点地图、优化页面性能、规范标签结构、合理布置内链。静态站SEO不靠花里胡哨的黑帽技巧，把基础项全部落地，收录效果一般都会不错。
